# Blog Migration from Jekyll Chirpy to Astro

Status: draft for review. Date: 2026-10-22.

## Summary

This project replaces the Jekyll Chirpy blog with an Astro site. The new
site takes its visual design from `~/src/pytorch-internals-course` and keeps
every Chirpy feature. The page layout is the only part that differs from the
course site, because a blog needs a post list, taxonomy pages, and a side
panel that a lecture site does not need. All 22 existing posts move to MDX,
and every existing post URL keeps working.

## Why

The owner wants a new theme. The course site already has the look the owner
wants: colors, Pretendard font, code style, dark mode, and interactive
widgets. The owner also wants to put interactive widgets in blog posts.
Jekyll with Liquid tags cannot do that cleanly. Astro with MDX can.

## Goals

- Use the course site's visual system without change: the CSS variables in
  `src/styles/global.css`, Pretendard, the accent colors (purple `#b509ac`
  in light mode, cyan `#2698ba` in dark mode), the `--fig-*` widget palette,
  Shiki `one-dark-pro`, KaTeX styling, and the theme toggle.
- Keep every Chirpy feature (list below).
- Keep LaTeX, Mermaid, and BibTeX citations.
- Let posts contain interactive widgets (Astro components in MDX).
- Keep every existing post URL, taxonomy URL, and the feed URLs.

## Non-goals

- Lecture structure. There are no "Week N" labels and no lecture ordering.
- Redrawing old figures as SVG. Existing images stay as they are.
- New content. Only the format of existing posts changes.
- Comments and analytics accounts. Their configuration is empty today, so
  the new site gets the slots but leaves them off.

## Anti-goals

The migration fails, even if it builds, when any of these happen:

- An existing post URL returns 404.
- A citation, an equation, or an image in an old post renders wrong or
  goes missing.
- The site looks like a generic template instead of the course site.

## Decisions Made by the Owner

### Starting point

Start from the course site's code (Astro 7, MDX, Tailwind 4, bun) and add
blog features to it. Chirping Astro (an Astro theme modeled on Chirpy,
<https://astro.build/themes/details/chirping-astro/>) is a reference for how
to build features such as search. Do not copy its styling, because it uses
daisyUI, which conflicts with the course CSS variable system.

### Visual design

Identical to the course site. Differences are layout only.

### Home page layout

Top navbar as on the course site, with: Posts, Categories, Tags, Archives,
About, a search button, and a theme toggle. The main column is a list of
post cards. Each card shows title, date, category, reading time, and an
excerpt. A narrow right panel shows "Recently Updated" posts and "Trending
Tags". On narrow screens, the right panel moves below the list. The list is
paginated (Chirpy uses 10 per page).

Mockup: `.superpowers/brainstorm/845435-1792678607/content/home-layout.html`,
option B.

### Post page layout

Course site layout: a sticky table of contents on the left of the article,
and a reading progress bar at the top. Below the article: the references
list, then previous/next post links.

Mockup: `.superpowers/brainstorm/845435-1792678607/content/post-layout.html`,
option A.

### Post format

Posts become MDX so that they can import widget components.

### Citations

Pandoc syntax through `rehype-citation`. A post names its BibTeX file in
front matter (`bibliography:`). In-text `[@key]` renders as an IEEE-style
number, and the references list is generated at the end of the post. The
existing per-post `.bib` files in `_bibliography/` are reused unchanged.

### Mermaid

Rendered in the browser. The Mermaid script loads only on pages that
contain a Mermaid block, and diagrams re-render when the theme changes.
Use an existing Astro Mermaid integration if one supports Astro 7
(needs verification). Otherwise, write a small client script.

## Feature Inventory

### Liquid tags in posts that need conversion

| Liquid tag | Count | Replacement |
| --- | --- | --- |
| `{% cite key --file name %}` | 72 | `[@key]` with `bibliography: name.bib` in front matter |
| `{% bibliography --file name %}` | 12 | Generated by `rehype-citation` (remove the tag) |
| `{% img src=... caption=... align=... style=... %}` | 46 | `<Figure>` MDX component (caption may contain HTML links) |
| `{% quote key --file name %}` ... `{% endquote %}` | 3 | `<Quote cite="key">` component: blockquote with a citation line |
| `{% youtube "url" %}` | 2 | `<YouTube>` from astro-embed |

Front matter fields in use: `title`, `author`, `date`, `categories`
(hierarchical list, for example `[Deep Learning, Diffusion, Vision]`),
`tags`, `math`, `mermaid`, `draft`. No post uses Chirpy prompt blocks
(`{: .prompt-info }`). No post uses Mermaid today.

### Chirpy features to keep

- Home list with pagination.
- Categories page and one page per category. Chirpy categories are
  hierarchical (first item is the parent).
- Tags page and one page per tag.
- Archives page grouped by year.
- About page (content from `_tabs/about.md`). The avatar
  (`assets/commons/avatar.jpg`) and social links (GitHub, X, LinkedIn,
  email) move to the About page and the footer, because the left sidebar
  goes away.
- Post table of contents.
- Search over posts.
- Dark mode with the toggle.
- Previous/next post links and related posts.
- Share buttons.
- Reading time and last-modified date. Last-modified comes from git
  history, as Chirpy's `posts-lastmod-hook.rb` does today.
- Code block copy button.
- Drafts (`draft: true`) are excluded from production builds.
- `sitemap.xml`, Atom feed, `robots.txt`, SEO and Open Graph meta.
- PWA: installable manifest and offline cache (enabled in Chirpy today).
  The owner wants it kept for visitors. Scope (Claude's call): a manifest
  for install, and a service worker that caches pages and images the
  visitor already opened. A new deploy must replace the cache, so that
  visitors never stay on an old page. Full parity with Chirpy's precache
  list is not required. The new service worker must take over the scope of
  Chirpy's `sw.min.js` for visitors who installed the old one.
- 404 page.
- Comment and analytics slots, off by default.

### URLs to keep

| Page | URL |
| --- | --- |
| Post | `/posts/:year/:month/:title/` where `:title` is the filename without the date, case kept (example: `/posts/2021/08/Topological-Overlap-Matrix/`) |
| Category | `/categories/<slug>/` (example: `/categories/deep-learning/`) |
| Tag | `/tags/<slug>/` (example: `/tags/amd-ryzen-cpu/`) |
| Feed | `/feed.xml` and `/atom.xml` |
| Pages | `/about/`, `/archives/`, `/categories/`, `/tags/`, `/page/N/` |

Slugs must match what Jekyll generates today. The current build in
`_site/` is the reference: compare its URL list with the new build.

Rules confirmed from `_site/`:

- `:year/:month` comes from the front matter `date`, not the filename.
  Example: `2018-07-14-Tox-Workflow.md` has `date: 2017-07-...` and is
  served at `/posts/2017/07/Tox-Workflow/`.
- Every level of a category list gets its own page. `[Deep Learning,
  Diffusion, Vision]` produces `/categories/deep-learning/`,
  `/categories/diffusion/`, and `/categories/vision/`. The slug is the name
  in lowercase with spaces replaced by `-` (`Server Engineering` becomes
  `server-engineering`). Tags follow the same rule. Chirpy's categories
  page still shows the parent/child tree.
- `_site/redirects.json` is `{}`. No old URL form needs a redirect.
- `feed.xml` (from jekyll-feed) and `atom.xml` (a custom template) both
  exist and differ. Both URLs stay. The new site serves the same Atom feed
  at both paths (Claude's call).
- `_posts/2026-10-12-Inside-vLLM.md` has `draft: true`. It is not part of
  the URL parity check, and it appears only in dev builds. It has
  `categories: [LLM Inference, vLLM]`, so `llm-inference` and `vllm`
  category pages appear once it is published.

## Constraints

- Package manager and runner: bun. Commands follow the course site:
  `bun run dev`, `bun run build`, `bun run test` (vitest, single run).
- Lint and format: oxlint and oxfmt, as on the course site.
- Astro 7 uses a Markdown processor that does not run remark/rehype
  plugins by default. Use the course site's `unified(...)` processor
  configuration so that `remark-math`, `rehype-katex`, and
  `rehype-citation` run.
- MDX treats `{` and `}` in prose as JSX. The conversion must escape them,
  and must not break `$...$` math.
- Images stay under their current public paths
  (`/assets/images/post/...`) so that image URLs do not change.
- Deploy: GitHub Pages at `https://blog.liam.kim`, built with bun in
  GitHub Actions. This replaces `.github/workflows/build-jekyll.yml`.
- The repository keeps its git history. Jekyll files are removed in the
  same branch. The `upstream` remote (Chirpy) is no longer needed.

## Calls Made by Claude

The owner did not decide these. The builder may revisit them.

- About page and footer hold the avatar and social links.
- Categories, Tags, and Archives pages use the course site's compact list
  style (date and title on one line).
- Conversion of the 22 posts is done by a one-time script, then reviewed by
  hand, instead of by hand alone.
- `.superpowers/` goes into `.gitignore`.
- Pin the course site's versions (Astro 7.3.5, `@astrojs/mdx` 8.0.2). If
  an integration does not support them, report it as a blocker. Do not
  downgrade Astro.
- `rehype-citation` is not proven on Astro 7. Prove it first with one post
  (Tensor-Program-2, 23 citations) before the bulk conversion. If it fails,
  fall back to a small custom remark plugin that keeps the same `[@key]`
  syntax, so that post sources do not change. Numbering follows the order
  of first citation (IEEE). `.bib` files move to
  `src/content/bibliography/` with their current names.
- Acceptance is automated: for each published post, compare the counts of
  images, KaTeX elements, citation links, and reference entries between
  `_site/` and the new build, and compare the full URL lists. A short
  visual pass over each post follows.
- `assets/` moves to `public/assets/` so that every asset URL stays the
  same. `favicon.ico` and `robots.txt` move to `public/`. Jekyll and Chirpy
  files are deleted: `_config.yml`, `Gemfile*`, `*.gemspec`, `Dockerfile`,
  `_includes/`, `_layouts/`, `_sass/`, `_javascript/`, `_plugins/`,
  `_data/`, `_tabs/` (after its content moves), `tools/`, `webfonts/`
  (Font Awesome, not used by the course design), the four Chirpy files in
`docs/` (`CHANGELOG.md`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`,
`SECURITY.md`; `docs/superpowers/` stays), and the
  Chirpy JS build files (`purgecss.js`, `eslint.config.js`).
- The deploy workflow checks out with `fetch-depth: 0` so that git-based
  last-modified dates are correct. The last-modified date shows only when
  it differs from the publish date.
